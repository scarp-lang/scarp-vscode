# Scarp Compiler & Runner v0.1.4 — Experimental Pre-release

> **Release candidate notes — not published.** This is a development preparation
> document. Do not tag or release a stable extension before the Scarp compiler
> has its first verified stable release.

Version v0.1.4 focuses on preventing stale diagnostic information, improving
compatibility with the latest official experimental compiler, and strengthening
the release pipeline. The extension still invokes the official Scarp CLI; it is
not an independent compiler or a language server.

## Verified project diagnostics

- **Reject stale results:** project verification detects edits to any local
  `.srp` source and `Scarp.project` manifest, including imported or previously
  clean files, while the compiler runs.
- **Detect external rewrites:** source snapshots include bounded SHA-256 file
  hashes. External editors and scripts cannot silently replace compiler
  results with diagnostics from an older file snapshot.
- **After verification:** VS Code file watchers, with a native filesystem
  notification fallback where supported, invalidate outdated project-owned
  Problems when local project files change.
- **When VS Code regains focus:** compare the last verified snapshots against
  disk to catch missed events. You can also run **Scarp: Check Verified Project
  Diagnostic Freshness** from the Command Palette.
- **Independent diagnostics:** unrelated standalone-file checks and other
  project roots retain their own Problems. Up to eight explicit project roots
  are monitored; evicting an old root also removes its stale diagnostics.
- **Bounded work:** snapshot verification has limits on total directory entries,
  source files, nesting depth and bytes. Symlinked directories and symlinks
  escaping the project fail closed rather than falsely reporting fresh results.

Checking diagnostic freshness never executes Scarp code, modifies source
files, or silently reruns verification. To refresh cleared Problems, invoke
**Scarp: Verify Project** manually. OS filesystem notifications are best effort;
a complete file change and reversal between snapshot checks is not guaranteed
to be detected.

## Compiler integration and output

- Prefer canonical `scarp exec` for running programs when supported; preserve
  the `run` fallback for older official compilers.
- Keep multi-byte UTF-8 compiler output correct across split pipe chunks.
- Validate release readiness against the actually published
  **Scarp v0.0.5-alpha.5** compiler, including `verify`, `exec`, interpreter
  project launching and read-only `inspect modules --json PROJECT_DIRECTORY`.
- Scarp alpha.5's experimental scalar C11 emitter is a **Rust embedding API**,
  not a general `scarp compile` command. Native executable building is not
  advertised as an extension feature.

## Release integrity

- Rebuild approved pre-releases from the exact GitHub tag and require the
  selected tagged commit to be reachable from the protected `main` branch.
- Verify the installable VSIX includes the compiled extension entrypoint,
  language grammar and configuration with the correct publisher, numeric
  version and experimental marker.
- Reject source, test fixtures, workflows, approval files, compiler checkouts
  and release scripts from the VSIX.
- If a GitHub release already has an attached VSIX, compare its entire archive
  member list and uncompressed contents with the freshly verified build before
  uploading it to either registry.
- Preserve the explicit release gate: ordinary commits and PRs do not publish.
  Stable releases are blocked until the compiler is stable.

## Compatibility and installation

- VS Code **1.96.0+**.
- Official Scarp compiler installed separately in the workspace extension host.
  Project commands require the compiler's actual `project_workflow` capability;
  the release-validation compiler is **v0.0.5-alpha.5**.
- Marketplace and Open VSX extension ID: `ScarpLang.scarp`.

When the version is approved for publication, use the same verified
`scarp-0.1.4.vsix` for the GitHub pre-release and both registries.
All artifacts and notes must remain marked **experimental pre-release**.
