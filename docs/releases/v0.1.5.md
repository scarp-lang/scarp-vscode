# Scarp Compiler & Runner v0.1.5 — Experimental Development Draft

> **Not published.** v0.1.5 is in development after the official
> [v0.1.4 experimental pre-release](https://github.com/scarp-lang/scarp-vscode/releases/tag/v0.1.4).
> A stable extension remains blocked until the official Scarp compiler has
> its first verified stable release.

## Responsive compiler verification and navigation

- A pending **Run Current File** now observes the version of the saved
  editor document. If that buffer changes or closes during compiler version
  detection or the `guide exec` capability probe, the obsolete compiler probe
  is stopped and no terminal is opened for the earlier saved source.
- **Stop Running Program** and compiler-path changes also terminate pending
  file Run probes promptly, using the existing bounded graceful/forced
  subprocess shutdown. Running terminals remain independently controlled.
- Real VS Code Extension Host regression tests exercise unsaved source edits
  during both compiler startup phases and Stop with stubborn child processes.

- Cancel obsolete file-verification subprocesses when the source document is
  edited or closed, or when `scarp.compilerPath` changes. The same scoped
  cancellation covers compiler version probing, static verification capability
  detection and the actual file check, not unrelated checks or Run terminals.
- Ignore canceled check results without showing a failure popup, overwriting
  previously completed Problems or interfering with unrelated files and projects.
- Go to Definition and Find All References also stop their compiler inspection
  promptly when VS Code cancels a request, the executable path changes, the
  requested editor closes, or an open Scarp source/manifest within the inspected
  root is edited. Unrelated directories do not cancel a valid lookup.
- Cancellation attempts graceful termination, then escalates to a bounded
  force-stop if a subprocess ignores the initial signal.
- Real VS Code Extension Host regressions exercise editor source changes,
  compiler switches and a stubborn compiler. Unit subprocess tests cover
  pre-cancellation, in-flight cancellation and cleanup.

## Cancellable project verification

- A project verification is stopped when an in-editor `.srp` source or
  `Scarp.project` manifest within that explicit project root changes, or
  when the configured compiler executable changes.
- Cancellation is scoped to the project being checked, covers the version
  probe, capability probe and actual static project verification process,
  and force-stops a stubborn compiler after a bounded grace period.
- Unrelated file verifications, projects, Run terminals and completed
  standalone Problems remain unaffected. External filesystem rewrites
  are still checked using before/after source snapshot validation.
- Real VS Code Extension Host regression tests confirm cancellation on
  source edits and compiler changes with a SIGTERM-resistant compiler.
- This does not add a background compiler, language server, source execution
  or an automatic project verification scheduler.

## Reliable verify-on-save scheduling

- Disabling `scarp.verifyOnSave` cancels any active automatic check for the
  affected file and prevents its output from publishing new Problems. Resource
  overrides remain respected; separately requested manual verification is
  never canceled solely because the automatic option changed.
- A real VS Code Extension Host test verifies both canceling a stubborn
  auto-check and allowing an explicit manual check to complete across the
  setting toggle.

- Keep the newest save event when an older queued rerun overlaps an active
  compiler check and another save remains in its debounce window.
- Preserve serial verification for each file and concurrency between files.
- Exercise the three-save race through real VS Code save events and compiler
  processes. The newest save must win; with early stale-check cancellation,
  an intermediate version may be checked before the final save arrives.
- Rapid consecutive saves are also tested with the published pinned compiler.
- Automatic verify-on-save remains opt-in, static-only and never launches the
  legacy evaluating `check` route.

## Safe release qualification

- Manually run the experimental release workflow from `main` with all three publishing boxes unchecked to execute the complete release gate and save a validated VSIX as a seven-day Actions artifact, without creating a public GitHub release or publishing to either registry.
- Creating or reusing a public GitHub experimental pre-release requires an explicit `publish_github` opt-in. Visual Studio Marketplace and Open VSX selections also require this consent; inconsistent combinations fail before expensive compiler tests.
- Published experimental release events retain automatic dual-registry publishing after verification of the approved tag and artifact.

## Manual publishing provenance

- Before packaging a manually dispatched pre-release, fetch the latest
  version tags and compare any existing `v0.1.5` tag's peeled commit against
  the exact checked-out `main` commit. Refuse a reused tag pointing elsewhere,
  even if the VSIX contents happen to compare equal.
- Support both lightweight and annotated tags. A missing version tag is
  permitted so the approved workflow can create it on the reviewed commit.
- Cross-platform tests construct real Git histories to verify absent,
  matching and mismatched tag behavior. No publishing is performed by these
  tests.

## Release-asset integrity

- Validate a first-upload VSIX before it is attached to GitHub: reject
  duplicated ZIP members, traversal/absolute paths, symlinks, encrypted
  entries, and missing `[Content_Types].xml` metadata. CI injects these
  malformed entries and requires the validator to reject the result.
- Compare literal ZIP member names and uncompressed payload bytes rather than
  matching `unzip -p` wildcard patterns. Mandatory metadata entries such as
  `[Content_Types].xml` cannot be silently skipped.
- Reject duplicate ZIP entry names and payload mutations. Streaming SHA-256
  permits differences in ZIP compression and timestamps, not file contents.
- CI checks mutations to both `extension/package.json` and
  `[Content_Types].xml`, plus an archive with a duplicate member.
- Preserve the exact approved-tag provenance, official compiler compatibility
  smoke test, trusted and Restricted Mode Extension Host integration suites,
  and explicit pre-release-only publication gate.

## Compatibility

- VS Code 1.96.0+.
- Official Scarp compiler installed separately in the workspace host.
- Release qualification remains pinned to Scarp v0.0.6-alpha.1 unless a newer
  compiler version is independently reviewed and approved.

These notes describe development work under review and do **not** authorize a
tag, GitHub release, Marketplace or Open VSX publication. All releases remain
experimental until the compiler is stable.
