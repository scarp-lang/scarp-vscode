## Release-asset integrity
## Responsive compiler navigation

- Go to Definition and Find All References stop their compiler-inspection subprocess
  when VS Code cancels the request (such as a superseded navigation query).
- Changing `scarp.compilerPath` while navigation runs also aborts that
  inspection; results from the previous executable are never returned.
- Cancellation attempts graceful process termination, then escalates to a
  force-stop for a stubborn compiler. It does not interrupt an unrelated
  compiler or an already-running integrated terminal.
- Regression coverage includes real VS Code Extension Host checks and Node.js
  subprocess tests for pre-cancellation, in-flight cancellation and cleanup.
- No background indexer, language server, automatic program execution, or
  native executable compilation is introduced.


- Compare literal ZIP member names and uncompressed file content instead of
  `unzip -p` filename patterns. Square-bracket metadata such as
  `[Content_Types].xml` must never be omitted from asset equivalence checks.
- Reject duplicate ZIP entry names to avoid ambiguity among ZIP consumers.
- Compare with streaming SHA-256 digests, allowing equivalent packages with
  different compression choices or ZIP timestamps while rejecting changed
  payload bytes.
- CI tests mutate `extension/package.json` and `[Content_Types].xml`
  separately, and inserts a duplicate required metadata member. All must fail
  the release comparison.
- Keep the approved-tag provenance, compiler compatibility smoke tests,
  trusted/Restricted Mode Extension Host tests, and pre-release-only publishing
  gate unchanged.

## Compatibility
## Reliable verify-on-save scheduling

- Retain the latest save notification across overlapping debounce windows and
  long-running compiler checks. An older queued rerun must not replace a newer
  save that has not finished debouncing.
- Continue to prevent concurrent verification of the same file, while unrelated
  files can verify independently.
- Add race regression coverage and ensure generic task payloads of
  `undefined` are still processed as legitimate reruns.
- Automatic verify on save remains opt-in and uses only non-executing compiler
  verification where supported.


- VS Code 1.96.0+.
- Official Scarp compiler installed separately.
- Validation uses the published Scarp compiler v0.0.6-alpha.1 unless a newer
  release is explicitly evaluated and approved.
