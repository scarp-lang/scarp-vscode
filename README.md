# Scarp Compiler & Runner

Official Visual Studio Code extension for the [Scarp language](https://github.com/scarp-lang/scarp). This is **experimental pre-release software** that calls the actual Scarp compiler; it does not reimplement the language.

> Never publish a stable extension until the Scarp programming language/compiler publishes its first verified stable release.

## Implemented

- **Compiler-free structural editing (development only):** native folding for Scarp blocks, comments, imports and regions; Expand Selection for nested expressions; verified local import links inside trusted workspace roots. Static editor assistance has bounded input size and never runs the compiler. Import links reject missing files and symlink escapes; Restricted Mode hides filesystem navigation while retaining folding and selection.

- **Compiler distribution reliability (development):** select the highest semantic version among complete native packages in the bounded release catalogue, rather than trusting publication order. Reject ambiguous release tags and duplicate archive/checksum names. Independently qualify the published v0.0.7-alpha.1 native installer on Windows x64, Linux x64 and Apple Silicon macOS, without removing historical jobs or publishing anything.

- **Current-document completion (development):** lexical suggestions for completed preceding bindings, mutable variables, typed function parameters, callable names, counted-repeat indices, destructured binding leaves and import aliases. Suggestions respect closed blocks, use the nearest visible declaration, and replace the complete identifier. No compiler, disk scan or network request; works with unsaved buffers and Restricted Mode. This deliberately does not infer types, resolve import members or captures, or support every callable header (contracts and complex syntax can omit local hints).

- **Editor assistance accuracy (development):** builtin hover, signature help and completion share a bounded lexical view. Completion replaces the whole identifier even when editing in its middle; qualified names and declarations split across lines are excluded; grouping and clipped editor windows no longer unnecessarily hide enclosing call help. This remains compiler-free lexical assistance, not semantic symbol resolution.

- **Published v0.0.7-alpha.1 editor reference (development):** versioned hover, completion, call highlighting and signature help for `array_concat`, `integer_hcf`, `softplus` and variadic `integer_gcd`/`integer_lcm`. Older binary GCD/LCM calls remain supported from v0.0.6-alpha.16; additional operands need v0.0.7-alpha.1. The installed compiler remains authoritative. A dedicated CI gate builds the exact published source, verifies golden examples and exercises the real Extension Host. Native ELF64 emission is a Rust embedding API, not a VS Code native-build command.

- **Published alpha.20 source compatibility (v0.1.6 development):** exact lowercase `d` numeric literals are separately highlighted from unsuffixed binary64 floats. Opt-in snippets demonstrate exact `0.1d + 0.2d` arithmetic and constant-index replacement on mutable tuples. New Scarp projects are created with lowercase `scarp.project` by compiler alpha.20; older uppercase manifests remain readable. CI builds the exact published alpha.20 source, checks both features and all 28 historical compatible snippets, and exercises a real VS Code Extension Host. No editor source is executed in the background and no VSIX is published.

- **Declarative `scarp.project` editor support (v0.1.6 development):** lowercase v2 project manifests now have their own VS Code language, TextMate highlighting for the compiler-defined `project`, `version`, `entry`, `type`, empty `dependencies {}` block, strings and `//` comments, brace-aware editing and a manual `sproject` starter snippet. This is lexical assistance only: project validation and compatibility remain the official compiler's responsibility. Legacy uppercase `Scarp.project` remains readable without being reclassified as a v2 manifest. Current published compiler versions and development `main` may scaffold different manifest formats; no project files are rewritten or commands run automatically.

- **Published Scarp alpha.18 persistent array updates (v0.1.6 development):** contextual highlighting plus editor-only hover, completion and typed signature help for the new pure `array_set(values, index, replacement)` built-in. It returns a new immutable `array<T, N>`, leaves existing aliases unchanged, checks index bounds (E0063), and charges cumulative array allocations (E0064). The metadata is version-labelled: older installed compilers do not gain runtime support. Published alpha.18 CI verifies and executes the compiler's official `array_updates.srp` golden fixture. No automatic execution or extension release.

- **Published Scarp alpha.18 default workspace entry (v0.1.6 development):** Run **Scarp: Run Workspace Entry (scarp exec)** in a trusted workspace and explicitly choose an opened local workspace root. The extension probes the installed compiler's `guide exec` for the alpha.18 implicit-entry contract and then launches `scarp exec` with no filename, using its official selection order: `scarp.project`, `Scarp.project`, `src/main.srp`, then `main.srp`. Terminal input works by default in the published alpha.18 compiler; no extra `--interactive` flag or `--input-file` option is added. The command rejects legacy compiler guides, missing entrypoints, unsaved Scarp files and changed source snapshots; it preserves Stop, duplicate-start prevention and Workspace Trust behavior. It never searches parent directories, starts automatically, or publishes an extension release.

- **Cancellable compiler setup and safe recovery (v0.1.6 development):** The explicit compiler setup wizard now shows cancellable progress for detecting a local compiler, validating a chosen binary, checking published release metadata, and installing the verified package. Cancelling a task leaves `scarp.compilerPath` unchanged; installer cancellation also interrupts the executable `--version` probe and cleans staging files. When an actual failure occurs, a contextual recovery prompt offers actions such as Retry Setup, Choose Compiler File, View Official Releases, or Open Compiler Settings. Integrity/unsafe-archive failures never bypass SHA-256 validation; existing invalid installed packages remain untouched. If compiler settings or workspace trust change while a request is in progress, a stale result is never selected automatically. No background installations, periodic update polling or release publishing are introduced.

- **Real published native package gate (v0.1.6 development):** CI now uses the *same* official GitHub downloader, SHA-256 checks, extraction and installer as the opt-in setup wizard against independently pinned **v0.0.6-alpha.17 and v0.0.6-alpha.19** public packages on Windows x64, Linux x64 and Apple Silicon macOS. It independently pins archive and checksum digests, checks the exact downloaded `scarp --version`, runs real static Verify and `exec` against the bundled hello fixture, proves clean installation and offline reuse, and launches a genuine VS Code Extension Host with that installed binary. Host assertions exercise Run, Verify, compiler-path resolution and Problems, and ensure the normal source actions add no installation directories. This catches archive/distribution defects that source-build compatibility tests cannot. The gate **consumes** published compiler assets; it does not publish a compiler or VSIX.

- **Scarp Compiler Manager (v0.1.6 development):** open **Scarp: Manage Compiler** from the Command Palette or the Scarp status-bar entry while editing a trusted `.srp` file. The manager explicitly checks the currently configured/discovered compiler, displays its version, resolved path, source and compatibility guidance, and can copy the validated path or open settings. **Check Official Compiler Updates** is a separate, user-selected network request: it compares the installed SemVer (including multi-digit alpha numbers) against the newest published native package for the extension-host operating system, then offers Setup or a release link. It never installs, executes a Scarp source, downloads a compiler, or changes settings without a further explicit action. Status-bar rendering itself performs no process or network probes. Remote windows inspect the remote host.

- **Explicit compiler setup wizard (v0.1.6 development):** Run **Scarp: Set Up Compiler** in a trusted workspace to detect an existing installation, select and validate an executable, open the official Scarp releases, or explicitly download the newest published native compiler package. The install action requires a modal confirmation, supports cancellation, validates GitHub asset SHA-256 digests and the official checksum sidecar, extracts only the expected compiler executable to versioned VS Code extension storage, checks its `--version`, and updates `scarp.compilerPath` on success. No downloads occur automatically while editing, saving, running or opening a workspace. Native install packages are currently Windows x64, Linux x64, and macOS Apple Silicon; other targets need a source build. Installed compilers are never silently overwritten.

- **Bounded compiler auto-discovery (development only):** when the default `scarp` command is missing from `PATH`, a trusted compiler action can locate a previously installed `scarp` executable in selected absolute `PATH` entries and common user/system locations on Windows, Linux and macOS. Only existing executable files with a valid `scarp --version` response are accepted. No drives, workspaces or Downloads are crawled; no compiler is downloaded or installed; and an explicit `scarp.compilerPath` is never replaced. Disable via `scarp.autoDiscoverCompiler` if needed. Remote workspaces search the remote extension-host machine.

- **Published Scarp alpha.17 editor compatibility (development only):** editor-only highlight, hover, completion, and typed signature help for `array_len`, `array_get_or` and `input_boolean`. Two new opt-in snippets demonstrate bounded fixed-array traversal and explicit interactive Boolean input. The fallback of `array_get_or` is evaluated even when the index is valid; typed input accepts only lowercase `true` or `false`. A pinned alpha.17 CI job exercises the official compiler and a real Extension Host. These hints do not execute source, silently install a compiler, or guarantee features in older compiler binaries.

- **Published compiler alpha.16 editor compatibility (development only):** editor-only highlighting, hover, completion and signature help for 19 new pure built-ins: `median`, `quantile`, six Unicode scalar/text utilities, seven signed-64-bit bit-pattern utilities, and four checked integer utilities. The help describes exact quantile bounds, UTF-8 scalar behavior, i64 overflow and execution quotas, but never evaluates source or promises availability on older installed compilers. A pinned alpha.16 GitHub Actions job builds the exact published compiler, verifies official statistics/Unicode/bitwise golden outputs and exercises a real VS Code Extension Host. This does not change the extension version, install compilers automatically or publish a release.


- **Published alpha.12/alpha.13 records, variants and Option/Result editing (development only):** contextual highlighting for nominal record/variant declarations and types, generic `option<T>` and `result<T, E>`, `new` constructors, `match on`/`case`, `needs`/`ensures` contracts, and binding-level `?` propagation. File Outline now lists top-level records and variants (including `pub`) without parsing or executing Scarp. Five new version-gated starter snippets cover records, variants, Option/Result, and propagation; immutable compiler jobs statically verify expansions and run official source/output fixtures. These are lexical/editor aids, not semantic analysis.

- **Published compiler alpha.12/alpha.13 immutable collection editing (development only):** contextual `list<T>`, `map<K, V>`, `[list: ...]` and `[map: ...]` highlighting; editor-only hover, completion and generic-aware signature help for four list and seven map built-ins. Immutable operations and the 4096/1024 entry limits are documented. Two opt-in starter snippets are checked against actual pinned alpha.12 and alpha.13 compilers in CI. Collection execution remains explicit using the separately installed interpreter; hints do not imply semantic checking, native compilation or silent execution.

- **Published compiler alpha.11 decimal editing (development only):** Exact `decimal` type highlighting and editor-only hover, completion and signature hints for `decimal`, `decimal_from_integer`, `decimal_to_integer`, `decimal_to_text`, `decimal_round`, `decimal_format`, `decimal_div_rounded` and `input_decimal`. Shows the alpha.11 version boundary, 28-digit/18-place exactness limits and explicit rounding modes. Existing explicit Run/Launch uses the separately installed compiler; Interactive Run supports `input_decimal` when the installed compiler advertises `--interactive`. No implicit conversion, semantic type checking or automatic execution is added.
- **Alpha.10 interactive execution (development only):** **Run Current File Interactively** and **Launch Project Interactively** explicitly enable `--interactive` for compiler-prompt input; normal Run and Verify stay unchanged. The extension checks the installed compiler's `guide exec`/`guide launch` output for `--interactive` before launching a terminal, and preserves Workspace Trust, saved-file snapshots and Stop behavior. Requires the separately installed published Scarp v0.0.6-alpha.10+ compiler. No automatic input prompts or input logging are added.
- **Alpha.10 fixed arrays and built-ins (development only):** contextual `array<T, N>` and `[array: ...]` highlighting; published input, stream-flush, BigInt power/radix/bitwise and EOF-aware helper signatures in hover, completion and signature help. An opt-in `scarp.maxArrayBytes` setting forwards the official array allocation budget only during explicit execution. No source is executed to offer editor help.
- **31 opt-in Scarp snippets:** type `sprint`, `sbind`, `svar`, `sif`, `sifelse`, `srepeat`, `swhile`, `sfunc`, `spurefunc`, `stuple`, `sread`, `stextint`, `stextfloat`, `sconditional`, `sbigint`, `sdecimal`, `sinputdecimal`, `slist`, `smap`, `srecord`, `svariant`, `soption`, `sresult`, `spropagate`, `sarraywalk`, `sinputbool`, `sdecimalliteral`, `stuplereplace`, `sarrayconcat`, `sintegerreduce` or `ssoftplus` in a `.srp` document. These are text expansions, statically compiler-checked in version-pinned CI, not semantic completion. Alpha.11 snippets require the published compiler v0.0.6-alpha.11+; collection and structured-type snippets require v0.0.6-alpha.12+; interactive decimal and Boolean input require explicit `--interactive` execution; the two alpha.17 snippets require compiler v0.0.6-alpha.17+; the two alpha.20 snippets require compiler v0.0.6-alpha.20+; the three new-series snippets require v0.0.7-alpha.1+.
- Recognize .srp files as Scarp, with a real TextMate grammar for the current Scarp compiler's declarations, functions, types, control flow, strings, numeric literals, operators, and line comments.
- **Native Scarp editing:** use VS Code's normal **Toggle Line Comment** shortcut (`Ctrl+/` on Windows/Linux, `Cmd+/` on macOS) to add or remove `//` without a custom keybinding; Scarp has no supported block comment syntax. Brace-aware editor rules indent lines after an opening `{` and dedent closing `}` lines, including Enter between braces. Wrap sections in `// #region NAME` and `// #endregion NAME` to fold them. These are editor-only conveniences; the official compiler still defines syntax and execution.
- **Optional file action CodeLens (v0.1.6 development):** enable `scarp.showFileActionsCodeLens` (off by default) to show **Run Scarp File** and **Verify Scarp File** directly above each local `.srp` document. Each action explicitly targets that file, even if the active editor changes. Merely displaying the lenses never executes code; the existing command handlers enforce Workspace Trust and check the target. The Verify command uses non-executing `verify` when supported, but older compilers may fall back to evaluating `check`. Disabled entirely in Restricted Mode.
- **Scarp: Run Current File:** launch the official compiler in the integrated terminal with program input/output. Prefer canonical `scarp exec` when the installed compiler advertises `scarp guide exec`, and retain legacy `scarp run` for older compiler versions.
- **Scarp: Verify Current File:** use the compiler's non-executing `verify` command when supported (Scarp v0.0.5-alpha.3+), including source-span JSON diagnostics in Problems. Older compilers fall back to the legacy evaluating `check` command.
- **Scarp: Explain Diagnostic Code (v0.1.6 development):** From a Scarp compiler error in Problems, choose **Explain Scarp E####** under Quick Fix/Code Actions, or run **Scarp: Explain Diagnostic Code** from the Command Palette and enter an uppercase error code such as `E0004`. This calls the installed compiler's existing `scarp explain E####` catalogue command **only after a user action**, with exact argument validation, a bounded process and no shell, file edits or Scarp program execution. Explanations appear in the Scarp Output channel. An unknown code may not be supported by an older compiler; update the separately installed compiler if needed. Both the action and command are unavailable in Restricted Mode.
- **Scarp: Show Compiler Version:** verify the executable. **Scarp: Manage Compiler** offers a read-only compiler health/status view and an explicit optional update check; **Scarp: Set Up Compiler** is the separate, confirmed installation action.
- **Scarp: Stop Running Program:** stop extension-owned terminal sessions and cancel file/project starts that are still waiting for compiler detection. Duplicate Run or Launch commands for the same source/project cannot open multiple terminals.
- Configure executable path, check timeout and eight legacy CLI resource budgets, plus four opt-in alpha.6 tuple/input resource limits.
- Preserve file paths with spaces by passing process arguments directly, without invoking a shell.
- Decode schema-v1 Scarp JSON errors into precise Problems ranges (including Unicode columns), with legacy human-readable diagnostic fallback. Preserve UTF-8 characters split across process output chunks.
- Keep Problems for independent .srp files separate; editing a file clears only outdated diagnostics from the affected verification.
- **Optional verify on save:** debounce rapid saves, use static-only verification where supported, and quietly refresh Problems without opening a terminal or displaying popups. In v0.1.5 development, obsolete file-check subprocesses are stopped when the checked buffer changes or closes, or when the configured compiler changes; unrelated file and project checks remain separate.
- **Outline / Go to Symbol in Editor:** show top-level Scarp `funcra` and `pure funcra` functions, `bind` / `var` declarations, `pub` exports, and `import ... as ...` aliases, without executing or compiling the file.
- **Built-in signature hovers (v0.1.5 development):** Hover over true calls to the published numerical, text, input and decimal built-ins (alpha.3 through alpha.11) to see typed signatures, version requirements and domain constraints. The bounded, local scanner skips quoted strings, line comments, declarations, qualified names and prefixed identifiers. No compiler, network connection or trusted workspace is required to show this reference; the actual compiler decides whether a call is valid and supported by the installed version.
- **Built-in signature help (v0.1.6 development):** In a Scarp built-in call, typing `(` or `,` displays the published typed signature and highlights the active argument (e.g. `top_p` or `text_replace`). This lightweight, bounded parser tracks nested calls, vectors, tuples, conditionals, comments and quoted strings without compiling code. It also works in Restricted Mode. It does **not** provide semantic type checking, user-function completion or a language server; the installed Scarp compiler remains authoritative.
- **Built-in IntelliSense suggestions (v0.1.6 development):** Type at least two letters of a published built-in (such as `text_re` or `top_p_`) and use VS Code completion, including `Ctrl+Space`, to see matching function names, typed signatures, constraints and minimum compiler versions. The feature uses only the local published-builtin reference catalog, does not execute source and remains available in Restricted Mode. It does not guess user functions, compile code, inject parameter lists or promise availability on older installed compilers.
- **Go to Definition / Find All References (compiler v0.0.6-alpha.1+):** invoke the official Scarp static source index on demand, resolving local and imported declarations (including named arguments). No background compiler process, caching across edits, runtime execution or invented definitions for builtins. Requires saved sources in a trusted workspace; older compilers retain editor-only Outline.
- **Browse Project Symbols (compiler alpha.1 of v0.0.6+):** select a trusted Scarp project root and search compiler-verified declarations across imported modules using a Quick Pick. The extension validates schema-v1 symbol IDs, canonical source paths and coordinates, and refuses to open outdated results when files change while the picker is open. No runtime statements or background indexing.
- **Browse Project Modules (compiler alpha.5+):** open an explicitly selected project's statically inspected module list in a Quick Pick, with entrypoint, import counts and public-symbol counts; select a module to open its source. No source is executed or changed. Malformed/out-of-root results, unsaved project buffers and external edits during inspection or selection are rejected. The browser checks saved source snapshots before and after compiler inspection and immediately before opening a module. Malformed module graphs with imports pointing to missing module IDs are rejected.
- **Scarp projects (compiler alpha.4+):** `Scarp: Create Project` invokes the installed compiler's `scarp create` to generate a new project; the compiler controls the actual manifest spelling and schema. `Scarp: Verify Project` checks the chosen project statically, and `Scarp: Launch Project` runs its declared entrypoint in an integrated terminal. In v0.1.5 development, a project verification stops its compiler subprocess when a Scarp source or manifest is edited or the compiler executable changes, without stopping unrelated checks or Run terminals. Project Launch also rejects unsaved source buffers, cancels obsolete compiler probes if project files change before terminal startup, and checks bounded disk source snapshots to catch external edits.

- **Initialize a declarative project (compiler alpha.8+ development):** **Scarp: Initialize Modern Project** calls the installed compiler's `scarp init`, generating that compiler's declarative manifest and starter application. Published alpha.19 and later compiler development builds may use different manifest casing; the extension recognizes both `Scarp.project` and `scarp.project` while associating the dedicated v2 editor language only with the lowercase filename. The command probes `scarp guide init` and rejects unsupported compilers, existing destinations and untrusted/nonlocal workspaces. **Scarp: Create Project** invokes `scarp create` without guessing that its output is always legacy. Neither command installs dependencies, runs source or publishes an extension.

- **Run Project Tests (compiler v0.0.6-alpha.8+ development):** choose **Scarp: Run Project Tests** in a trusted workspace with an explicit `scarp.project` or legacy `Scarp.project` root. The extension checks the actual compiler's `guide test` support before opening a terminal, rejects unsaved project sources and sibling `tests/*.stdin` fixtures, and fingerprints test source/fixture inputs during startup so obsolete launches are cancelled. This is a user-initiated execution of ordinary Scarp test programs and does not run automatically on save. The terminal displays the compiler's own PASS/FAIL report. No test outcome is fabricated by the extension. Older compilers receive an explanatory error. Test fixture edits after terminal launch are not monitored by the extension.

- **Optional nonempty project test suite guard (compiler alpha.8+ development):** Set `scarp.requireNonemptyProjectTests` to `true` in VS Code Settings for a project to add the compiler's `--require-tests` option whenever you explicitly run **Scarp: Run Project Tests** or **Scarp: Run Filtered Project Tests**. An empty test directory or unmatched filename filter then returns a failing status instead of an apparently successful zero-test suite. Default is `false` for backward compatibility. This does **not** automatically run any tests, affect static test discovery, alter source files or bypass Workspace Trust; it requires a separately installed compiler with published alpha.8 test support.

- **Run filtered project tests (compiler alpha.8+ development):** Run **Scarp: Run Filtered Project Tests** to enter a literal, case-sensitive UTF-8 substring of a test filename (for example `addition`) and choose a trusted Scarp project root. The extension launches `scarp test --filter SUBSTRING -- PROJECT` only on explicit request. This is not an exact-name selector, glob or regex: multiple filenames containing the substring can run, and an unmatched filter may run zero tests. The compiler enforces its published project/test limits and reports actual outcomes. The extension validates the 128-byte filter limit, rejects path separators, controls, colons and leading dashes, and retains saved-source, fixture and startup checks. Requires the separately installed v0.0.6-alpha.8+ compiler; never runs tests on save or in Restricted Mode.

- **Cancellable read-only test discovery (v0.1.6 development):** **Scarp: List Project Tests** now cancels its compiler subprocess immediately when a Scarp source or project manifest changes in the selected root, or when the configured compiler changes. Duplicate concurrent listings for the same project are rejected. Unrelated projects remain unaffected; the existing filesystem snapshots still detect external edits. Cancellation does not run Scarp tests, publish diagnostics or open a terminal.

- **Filtered read-only test discovery (compiler alpha.8+ development):** Use **Scarp: List Filtered Project Tests** to enter a literal case-sensitive filename substring (e.g. `addition`) and browse only matching `tests/*.srp` files, without executing any Scarp program. This uses the official compiler's `test --json --list --filter` interface and keeps the same validated schema, project snapshot, workspace trust, safe file-open, cancellation and source-change checks as unfiltered discovery. Filename filters are 1–128 UTF-8 bytes; globs, paths, controls, and leading dashes are rejected. No matches display an informational message and do not open a terminal. A filtered **Run** is a separate, explicitly executable command.

- **Read-only test discovery (compiler alpha.8+ development):** **Scarp: List Project Tests** asks the official compiler for `scarp test --json --list` in a trusted, explicitly selected project. It does not compile, run, or evaluate any test source. The bounded schema-v1 decoder rejects traversal, nested paths, duplicate names and unexpected test statuses. Select a validated test file to open it without launching the program; stale disk snapshots, symlinks, unsaved project files and older compilers are rejected. A zero-test project displays an informational message, not a fabricated success.

- **Explicit BigInt execution budgets (published compiler alpha.9+):** Set `scarp.maxBigIntDigits` (0–1,000,000; unset uses the compiler's 10,000 default) and/or `scarp.maxBigIntBytes` (nonnegative safe integer; unset uses 8,388,608 bytes) to forward the official `--max-bigint-digits` / `--max-bigint-bytes` quotas on explicit **Run File** and **Launch Project** operations. The first limits the number of raw decimal constructor digits and normalized result digits; the second limits cumulative logical limb/scratch allocations, **not** physical RAM or BigInt computation time. A zero limit is valid but restricts construction. These settings are opt-in, checked for safe integer values (and the published digit ceiling), are not forwarded to static Verify or test-list discovery, and older compilers do not accept them. Do not enable these flags with a pre-alpha.9 compiler.

- **Published compiler alpha.9 BigInt editor compatibility (v0.1.6 development):** The editor now lexically distinguishes the contextual `bigint` type from calls to `bigint("decimal")`; recognizes `bigint_from_integer`, `bigint_to_integer`, and `bigint_abs`; and offers compiler-free hover, completion, signature help, and a verified `sbigint` starter snippet. These features require the separately installed Scarp `v0.0.6-alpha.9+` compiler to execute. `integer` remains signed 64-bit; `bigint` is an exact, bounded, interpreter-only type (10,000 decimal digits and 8 MiB logical limb quota by default). Conversion to `integer` fails on overflow; `bigint` does not implicitly mix with `float`/`integer`. The extension does not implement BigInt arithmetic itself. CI pins the exact published alpha.9 source and verifies the compiler's real BigInt examples and snippet expansions. The new compiler's `test --json=v2` structured reports are not yet interpreted in the editor; the existing stable `--json` v1 test listing remains unchanged.

**Alpha.7 editor compatibility:** The `sconditional` snippet expands to the new typed interpreter-only `if`/`else` value expression. The grammar also highlights lexical `\u{HEX}` Unicode scalar escape sequences inside Scarp strings; the official compiler, not the editor, validates scalar values. The pre-release extension is tested against the immutable v0.0.6-alpha.7 compiler source alongside earlier compiler compatibility gates.

**Syntax highlighting:** The grammar is editor-only, does not execute code and follows official Scarp token spelling. It highlights the published v0.0.6-alpha.3 `topk`, `topk_values`, `softmax_temp` and `logsoftmax_temp` calls, plus v0.0.6-alpha.4 `sample_area`, `sample_slopes`, `sample_cumulative_area` and `cosine_similarity`, and v0.0.6-alpha.5 `top_p`, `top_p_values` and `pearson_correlation`, only in call positions. The published alpha.6 compiler also adds the six scalar/text conversion helpers and `read_line` plus contextual `tuple<...>` syntax. Strings, comments, longer names and user declarations are excluded by tokenizer tests. Older installed compiler versions may not implement every highlighted call; the extension invokes the separately installed compiler.

**Compiler-backed definition/reference navigation** uses the v0.0.6-alpha.1 static `inspect references --json` schema. Right-click on a Scarp symbol and select Go to Definition or Find All References, or use VS Code's normal navigation shortcuts. Only saved, trusted local projects are inspected. If an explicit workspace root contains `Scarp.project`, the full project graph is examined; otherwise the active .srp file is the root. Compiler semantic errors and older compilers can return no navigation results. Results belong to a single compiler snapshot. Bounded local source hashes are checked both before and after compiler inspection and again before returning locations; if any project source changes in that interval, outdated results are discarded. In v0.1.5 development, canceled navigation requests, edits to Scarp files within the inspected root, and compiler-path switches promptly terminate obsolete CLI inspections. Unrelated source roots remain independent. Navigation remains on-demand, and later edits require reissuing the command. Files are never executed.

**Browse Project Symbols** is available in the Command Palette for a Scarp project folder containing `Scarp.project`. The compiler's static `inspect symbols --json` view includes lexical declarations from the valid project graph; builtins without source definitions are excluded. Save project files before browsing. Select a declaration to jump to its actual source; invalid or changing source metadata is rejected.

**Restricted Mode:** When a folder is untrusted, Scarp offers syntax highlighting, local read-only Outline and static built-in signature hovers only. The Run, Verify, compiler version, compiler-backed navigation and project commands require Workspace Trust; their command-palette/editor menu entries are hidden until trust is granted, and direct command invocation is rejected. The configured compiler is not launched by verification-on-save in Restricted Mode. A separate real VS Code Extension Host test validates this behavior.

**Built-in hover reference** is lexical rather than semantic and covers the 18 versioned numerical, text and input functions; it does not verify types, execute Scarp, inspect imports, index declarations or guarantee support in an older separately installed compiler. It does not attempt to provide hover help on very long lines (over 16,384 UTF-16 code units), or across more than one line between the name and the opening parenthesis.

**Outline navigation** is intentionally limited to file-scope declarations. It uses a tolerant editor scanner; definitive syntax and semantics remain the official compiler's responsibility. Local variables are not shown in the Outline. No compiler installation or workspace trust is needed to navigate a document.

**Not yet supported:** native executable compilation, project builds that emit executables, package registries or dependency management. Scarp compiler v0.0.5-alpha.4 supports interpreter-backed project creation, static verification and launching only. No fictional implementation is provided.

## Install and run

1. From a trusted VS Code workspace, run **Scarp: Set Up Compiler** in the Command Palette, then choose **Install Official Scarp Release**, **Detect Existing Compiler**, or **Choose Installed Compiler File**. You can also install manually from [official compiler releases](https://github.com/scarp-lang/scarp/releases).
2. The wizard validates `scarp --version` (or the selected binary). To configure manually, set **scarp.compilerPath** to the executable file (Windows example: `C:\tools\scarp\scarp.exe`). The optional installer checks both published SHA-256 digests and the archive's official checksum sidecar before accepting a binary.
3. Install a verified pre-release VSIX when available, or open the repository in a VS Code Extension Development Host. If the default compiler command is absent from PATH, Run or Verify can automatically locate an existing Scarp installation in common folders.
4. Open a .srp file in a trusted workspace, then use Run or Verify in the Command Palette.

~~~scarp
print("Hello from Scarp!");
~~~

The extension uses the workspace extension host. On Remote SSH, WSL or containers, compiler management, update checks, setup and installation target that environment, not the local client machine. CI separately tests the actual official published native compiler packages, not just source-built compiler compatibility. Downloads require your explicit confirmation and are limited to published GitHub Scarp release assets. The installed binary is kept in VS Code extension storage, not your source project, and no automatic compiler updates occur.

## Experimental native object export (development)

The published Scarp v0.0.7-alpha.2 compiler introduces the `native-object` CLI.
In a trusted workspace, open a saved standalone `.srp` file and explicitly run
**Scarp: Export Native Object (Experimental)** from the Command Palette.

- Select a checked function, a bounded function, or a bounded nonrecursive call graph.
- Enter the unsigned 32-bit work/stack allowances and entry name when requested.
- Choose a new local `.o` destination with an existing parent directory and confirm.
- The extension probes the installed compiler's actual `guide native-object` contract,
  freezes the saved UTF-8 source, preserves the compiler lookup context used during
  capability probing, checks the published schema-v1 ABI report and ELF64
  header, then publishes without overwriting any existing path.
- ABI and failure-span metadata and the raw source SHA-256 are printed in the Scarp
  Output channel, including a preview of up to 64 spans translated to one-based
  editor lines and UTF-16 columns. The full JSON retains the original half-open
  UTF-8 byte ranges; keep the source snapshot unchanged when diagnosing failures.

This generates **x86-64 ELF64 relocatable objects only**, including when VS Code
runs on Windows or macOS. It is not a native program runner, linker, executable,
OS builder, C compiler, or replacement for the existing interpreter Run/Verify
commands. Source is not automatically saved or changed. An unsupported compiler,
invalid source, stale source/configuration, or cancellation before publication
prevents the final output. The destination filesystem must support hard links;
no unsafe overwrite or copy fallback is provided. The command is disabled in
Restricted Mode and no background compilation is performed.

See the [published compiler native object contract](https://github.com/scarp-lang/scarp/blob/v0.0.7-alpha.2/docs/native-object-output.md).

**Project commands:** Open the project folder containing `scarp.project` or `Scarp.project` in VS Code, then choose **Scarp: Verify Project** or **Scarp: Launch Project** from the Command Palette. In multi-root workspaces, select the explicit project folder. The extension does not search parent directories for a manifest. **Scarp: Create Project** asks for the parent workspace folder and a new directory name; the compiler refuses to overwrite any existing path. Project commands are available only when `scarp diagnose --json` reports `project_workflow: true` (official v0.0.5-alpha.4+). A missing compiler or an older release produces an explanatory error, not a simulated result.

These commands run the real interpreter and static compiler, **not** native executable generation. `verify` never uses run budgets or executes normal runtime statements; `launch` uses the configured run budgets. Project diagnostics with source locations are added to Problems. Manifest errors without source locations remain visible in the Scarp Output channel.

With a Scarp v0.0.6-alpha.8 candidate compiler, existing project commands also accept the declarative manifest created by `scarp init`. The extension highlights `assert` as a language statement. The selected compiler determines which syntax and project format it supports.

**Browse project modules (v0.1.4):** With Scarp v0.0.5-alpha.5 or later installed, open a trusted project folder containing `Scarp.project` and choose **Scarp: Browse Project Modules**. Pick a module to open it. The extension calls `scarp inspect modules --json` on the explicit directory, never runs Scarp program statements, does not perform implicit project discovery, and refuses to browse unsaved project source. Inspection errors go to the Scarp Output channel. The browser validates schema version, source paths, file types and project-root containment. Module metadata reflects the files on disk when inspected, not unsaved changes or an always-updating language server.

**Module-inventory compatibility (development):** The extension accepts compiler inspection schemas 1, 2 and experimental schema 3, which extends type signature strings for fixed-size arrays. Browsing still verifies module paths, graph edges and bounds, and cannot execute project source. Schema 3 is only available in compatible compiler development builds; it is not a claim that the published alpha.8 compiler supports fixed arrays.

**Project verification safety (v0.1.4):** Save open `.srp` files and `Scarp.project` before verifying. A project verification is skipped if there is already one running for the same root. If an open project file or manifest changes while the compiler is checking, its outdated result is discarded instead of updating Problems; verify again after saving. Once a project check finishes, editing any local `.srp` file or `Scarp.project` in its root clears that project's previous Problems—even if the edited file had no errors—without erasing independent checks. In v0.1.4, a bounded SHA-256 source snapshot also detects external edits, additions and deletions of local `.srp` files and the root manifest **during verification**; changed snapshots discard outdated results. The scan is limited to 20,000 directory entries, 4,096 source files, 32 directory levels and 64 MiB of input bytes. It fails closed for symlinked directories and source symlinks escaping the selected root. After a completed project verification, scoped VS Code file watchers, with a native recursive filesystem notification fallback when supported, listen for local `.srp` source and root `Scarp.project` creates/changes/deletions. When an event arrives, the extension removes outdated project-owned Problems without automatically re-running code or verification. At most eight explicit verified roots retain watchers; evicting an older root also removes its Problems rather than retaining stale diagnostics. Watching stops on invalidation, replacement or extension disposal. File watchers are best-effort and subject to VS Code filesystem watcher exclusions and operating system limitations; they do not monitor sources outside the project, guarantee detection of every external change, or detect a change reverted between verification snapshots.

**Reconcile verified diagnostics:** When VS Code regains focus, Scarp compares saved, bounded SHA-256 source snapshots for up to eight explicitly verified project roots. If external changes were missed by filesystem watchers, only that project's old Problems are cleared; no compiler or program is launched. Use **Scarp: Check Verified Project Diagnostic Freshness** in the Command Palette to run the same check manually. Re-run **Scarp: Verify Project** to refresh diagnostics. This checks only tracked roots and does not automatically monitor or scan every workspace. Unexpected read errors fail closed by clearing the affected project's stale diagnostics.

Unspecified limits use compiler defaults.

## Limitations

- The Scarp language is still alpha and can change. Compatibility must be verified against the real compiler.
- For Scarp alpha.6–alpha.9, `read_line()` consumes redirected/piped UTF-8 input; a connected integrated terminal reports E0054 for a selected read. Published alpha.10+ adds explicit terminal input when you choose **Scarp: Run Current File Interactively** or **Scarp: Launch Project Interactively**. The installed compiler's `--interactive` option (not an extension-emulated prompt) handles `read_line`, `input(prompt)` and related calls. Ordinary Run remains noninteractive; `--input-file` is also available in alpha.10+ through a separate CLI invocation. Unselected reads do not fail.
- With older compilers, the legacy `check` command can evaluate reachable code; the newer `verify` command does not.
- Diagnostics use schema-v1 JSON errors with newer compilers, or human-readable errors with older compilers. Unlocated errors are shown in the Scarp Output channel.
- Only one terminal session per file; terminal output is not duplicated into Problems.
- With older Scarp compilers, `Scarp: Verify Current File` falls back to the legacy `check` command, which may evaluate program statements. For non-executing verification, install Scarp v0.0.5-alpha.3 or a newer compiler exposing `verify --help`.
- Runtime budget settings apply to execution and the legacy evaluating `check`; they do not apply to static `verify`.
- **Verify on save safety:** disabled by default; only works in trusted workspaces, with saved local `.srp` files, and on compilers supporting non-executing `verify` (v0.0.5-alpha.3+). Older compilers are skipped, never silently executed.
- Save events are coalesced for 300 ms per file and serialized. Errors update Problems and the Scarp Output channel without intrusive notifications; manual **Verify Current File** retains its existing behavior.
- Unsaved document changes are saved first when invoking manual commands.
- Native build, native compilation, code completion, AI coding, and debugging are out of scope. Compiler-backed Go to Definition and Find All References are available on v0.0.6-alpha.1+.

## Troubleshooting

**Compiler missing:** verify it is installed in the same workspace host as VS Code. Set scarp.compilerPath if it is not on PATH.

**Invalid version:** verify the setting points to an official Scarp executable, not a shell command or another program.

**Check failed without Problems:** use **Scarp: Show Compiler Output** to see the full stderr.

**Paths containing spaces:** do not add wrapping quotes inside scarp.compilerPath.

## Marketplace and Open VSX pre-releases

The official publisher and extension identifier are `ScarpLang.scarp` on both Visual Studio Marketplace and Open VSX. Only verified **pre-release** builds are permitted until Scarp's compiler publishes its first stable release.

The [publishing workflow](.github/workflows/prerelease.yml) supports both registries. Publishing a reviewed **GitHub pre-release** automatically publishes the same verified VSIX to both registries; normal commits and stable releases never trigger registry publishing. Maintainers can also run the workflow manually from `main`: by default it **only qualifies and saves a temporary VSIX artifact in the Actions run, without publishing a GitHub release or registry version**. Public release creation requires checking `publish_github`; either registry option additionally requires that GitHub release approval.

Marketplace authentication uses its GitHub OIDC Trusted Publisher policy for `scarp-lang/scarp-vscode` and workflow `prerelease.yml` (no Marketplace PAT). Open VSX has a verified `ScarpLang` namespace and the published `v0.1.1` pre-release. The current workflow still uses a scoped publishing token in the `OVSX_PAT` Actions secret. Tokenless Open VSX Trusted Publishing is eligible, but requires namespace-owner registration and a reviewed workflow migration before the secret can be removed. See the [release instructions](docs/RELEASING.md) for setup, exact version/tag requirements, and release guards.

The Extension Host integration tests run an actual copy of VS Code and need the `SCARP_TEST_BINARY` environment variable set to the absolute path of a compatible official Scarp executable. In Linux CI, this is built from the pinned compiler tag and launched under `xvfb-run`. These development tests do not publish a new extension version.
